2 — Vision: doc-native agentic workspace

Not “chat + files”. Chat over files with traceable actions.

Target
One sentence: OpenChat v2 is an agent that ingests any document collection (PDFs, docx, md, csv, images, URLs, repos), grounds every answer in cited chunks, and can act via tools (search, read, write, code-run) with a verifiable trace.
North star UX: User drops 37 PDFs + a Notion export → asks “summarize risks vs our contract” → agent retrieves top 12 chunks (≤200ms pgvector ANN), shows plan → executes 3 tool calls → answers with inline citations + side doc viewer.

Product changes vs today

  • Documents first — Projects / Collections as primary nav (not just Chats). Drag-drop anywhere ingests.
  • Agent, not model — Model picker becomes Agent preset (Researcher, Analyst, Builder) + underlying model.
  • Trace instead of stream — Streaming tokens plus intermediate thought → tool_call → observation → answer with collapsible steps.
  • Grounding by default — Every factual sentence can show source chunk + confidence.
  • Actions — Agent can create docs, run code (sandboxed), open PR-like diffs, email, calendar — gated by permissions.

Loop spec (what replaces provider.ts)

// lib/agent/run.ts  — single source of truth
type AgentContext = { chatId, projectId, actor, docCollectionIds, budget };
async function* runAgent(input: { messages, context }): AsyncGenerator<AgentEvent> {
  planner → { subTasks }                          // optional 0.5s LLM call
  for (let turn=0; turn<MAX_TURNS; turn++) {
    retrieved = await retrieve({ query: lastUserMsg, collectionIds, topK:12 });
    llmStream = await callModel({ messages, tools: TOOL_REGISTRY, retrieved });
    for await (chunk of llmStream) {
      if (chunk.tool_calls) yield { type:'tool_call', ... }
      else yield { type:'token', text: chunk.text }
    }
    if (requiresTool) { obs = await executeTool(call, context); messages.push(obs); }
    else break;                                   // final answer
  }
  yield { type:'done', citations: retrieved.map(r=>r.citation) }
}

3 tiers: ephemeral (turn), episodic (pgvector chat_history), semantic (project collections). Summarizer compresses > 12k tokens → rolling summary row.

  • Older → summarized + cited
  • Per-doc memories (key facts)

Accepted inputs (v1)

  • Files: PDF (text + scanned image → Tesseract / vision OCR), DOCX, PPTX, TXT/MD, CSV/JSON (table-aware chunking), images (PNG/JPG → caption via vision model)
  • URLs: single page + sitemap crawl (max 25 pages / job)
  • Repo: whitelisted globs under project root, read-only via ingest_repo_files tool

Pipeline stages (queue = pg-boss / BullMQ on Redis or Inngest if serverless)

  1. Upload — client gets S3 presigned POST (Supabase Storage or R2), uploads direct; row in documents status=pending
  2. Parse — worker: pdfjs + mammoth + csv-parse + sharp+tesseract fallback; normalize to markdown + page map
  3. Chunk — semantic splitter (heading-aware, 480-560 tokens, 80 overlap), keep page, heading, char_offset, hash
  4. Embed — batch 96 chunks/call to provider; retry with backoff; store in document_chunks.embedding vector(1536)
  5. Index — HNSW already; hybrid search = vector (0.7) + BM25 tsvector (0.3) + recency boost
  6. Cite — each chunk → stable citation {docId, title, page, chunkId} rendered inline in UI
Target numbers: 100-page PDF → ~190 chunks → ~3.2s end-to-end on 2 workers. P95 retrieval 140ms (HNSW ivfflat → hnsw m=16 ef=64) for topK=12 over 200k chunks.

Reuse today

.uploads/ + files table → replace with documents + document_chunks + object storage. Keep idea of getOwnedFiles ownership check, but enforce via RLS on project_members.

9 — API & streaming contract

Stable even while internals change

sse

Agent run (replaces /api/chat/send)

POST /api/agent/run
{ chatId?: string, projectId: string, message: string,
  mentionDocIds?: string[], agentPreset?: "research"|"analyst"|"builder" }

→ 200 text/event-stream
event: meta       data: { chatId, traceId }
event: token      data: { text }
event: tool_call  data: { id, name:"search_documents", input:{query} }
event: tool_result data: { id, output:{ chunks:[{docId, page, score}] } }
event: citations  data: { citations:[{docId, title, page, chunkId, score}] }
event: done       data: { chatId, usage:{prompt,completion} }
Why SSE not WebSocket? Works through Vercel/Next streaming, easy to proxy, resume via Last-Event-ID. Client fallback: chunked fetch reader same as today readAssistantStream().
